# Import format v1

The two files in `templates/` contain synthetic examples only. Supported: UTF-8 comma-delimited CSV with quoted cells and newlines; maximum 2 MB and 10,000 rows. Headers can be mapped in the import UI. Documents and statements are data, never executable instructions. The original CSV text is discarded after hashing and parsing; parsed rows retain provenance.

Required for all rows: `identifier`, `name`, `instrument_type` (`MF`, `STOCK`, `ETF`), `account`, `date`, `type`. Currency defaults to INR; other currencies are rejected. Use masked account references. Use the actual scheme code or an ISIN plus listing-specific identifier for stocks. Identity is identifier + instrument type + MF plan + MF option, with separate account lots. Direct/Regular and Growth/IDCW never merge by name.

MF rows require exact `plan` (`Direct` or `Regular`) and `option` (`Growth` or `IDCW`). Purchases, redemptions and reinvestments require positive units, a price and gross amount. Optional `fees` is nonnegative and defaults to zero. Prices and amounts are source decimals with at most 8 decimal places. `source_reference` is strongly recommended; references must identify unique source events. `settlement_date` is optional and distinct from transaction date. `valuation_date` is optional: when supplied with price, it records a dated source valuation. Do not use transaction price as a current NAV without an actual matching valuation date.

Supported events: BUY, SELL, OPENING, DIVIDEND, REINVEST, FEE, SPLIT, BONUS, TRANSFER_IN, TRANSFER_OUT. SPLIT uses the new/old unit ratio in `price`. BONUS is additional units at zero accounting cost, not a tax determination. OPENING and transferred-in units without acquisition provenance have unknown basis and dates. Transfers are excluded from consolidated external cash flows; their full lot history is not reconstructed. Model a switch as linked source sale and destination purchase, and verify gross proceeds and reinvested amounts. The UI does not automatically link switches.

Unsupported mergers, demergers, segregated units and reversals of individual source events are rejected. Reverse an entire posted import batch from Import center; history is preserved. A reversal that would leave a subsequent oversell is rejected. Corrections require reversing the relevant batch and creating a corrected import. Records are immutable events; batch state controls their active effect.

Optional `closing_units` validates the resulting account/instrument units for the newly imported batch. Import a complete relevant period in one batch and provide closing units on the final row. Existing old batch closing snapshots are not reused to veto later valid purchases. This is not a general dated statement-balance reconciliation engine. `asset_class` optionally accepts Equity, Debt, Gold, Cash, Other, Unclassified. Category text alone does not establish a verified regulatory classification.

Identical files return the same active preview. Source-reference duplicates are excluded. Economically identical events with distinct or missing references require explicit review as separate legitimate purchases. Posting rechecks against the active ledger. Posting and audit updates use one database batch. Keep source references consistent across overlapping exports. Do not rely on this prototype as a concurrent institutional reconciliation system.

Original files and statement passwords are not retained. Statement PDF/CAS and broker-specific export parsers need representative fixtures and a documented supported format before implementation. No provider account or broker API is invented.
